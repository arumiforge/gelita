## Installer for the ElevenLabs backup narration: `gelita:narration:install` (14 November 2026, branch `claude/ai-studio-multi-session-74p683`)

Owner request after PR #354: build the installer now. The owner named the model (ElevenLabs v4) and the voice made for Mbah Kedu in ElevenLabs ("Mbah Kedu"). This closes the *Not done* item of the section above; that section expected the installer only after a first accepted batch, because the profile text depends on model and voices. Those two are now known for Mbah Kedu in Indonesian, and the installer reads the rest from `voices.md` when it is filled in.

1. **Command** `php spark gelita:narration:install [--dir=FOLDER] [--dry-run] [--timpa]` (`App\Commands\NarrationInstall`, rules in `App\Libraries\SyntheticNarrationInstaller`). It copies `FOLDER/out/{id,en}/{code}.{mp3,m4a,ogg,wav}` to `public/assets/audio/narasi/{id,en}/` and lists each file in `produksi.json` (`files.{locale}.{code}` = `sha256`, `voice_profile`). Default folder `ai-studio/elevenlabs-voice`; relative paths from the repository root. It writes files only; `gelita:narration:import` registers them, as before.
2. **Voice profile from `voices.md`.** The line `ElevenLabs model:` and the first table (speaker, voice per language, settings) give `ElevenLabs {model} · {voice} · {settings}`, cut at 200 characters. A value in italics (the "_not chosen yet_" placeholder) counts as empty. The sheet stays Markdown, not JSON, because the owner and the tool fill it in by hand; a test reads the real file so a changed table layout is noticed.
3. **All or nothing on voices.** If the model, or the voice of a speaker and language that has takes in `out/`, is missing, nothing is copied. A take without a profile would be stored as `tts` with no trace of what made it.
4. **Voice actors first, enforced.** A line keeps its real recording, and the take is reported as kept, when (a) the narration folder holds a file for that code whose sha256 is neither the take's nor the manifest's (an earlier ElevenLabs take), or (b) the database holds an active `own_recording` for `audio.narasi.{locale}.{code}` with other content (a panel upload). Without (b) the import would replace a panel upload: a freshly copied file is newer than the upload, and `importOne()` lets the newer one win. `--timpa` replaces real recordings too and deletes a real file of another extension, since the import picks by extension order.
5. **Manifest before files.** The manifest is written (to a temp file, then renamed) before any take is copied: a listed file that is not there yet is harmless, a copied file that is not listed would be imported as a real voice. If the manifest cannot be written, nothing is copied.
6. **Deviation: one change in `NarrationImporter::importOne()`.** A file whose content is already installed is "unchanged", and its row was left as it was. If someone had copied takes by hand and imported them before the manifest existed, they stayed `own_recording` for good. Now an unchanged file that the manifest lists is corrected to `tts` + `voice_profile`, with its approval kept. Only in that direction: a missing manifest proves nothing, so `tts` rows are never turned back (servers that still hold the old TTS takes without `produksi.json` are untouched). New public methods `manifestPath()` and `reloadManifest()`.
